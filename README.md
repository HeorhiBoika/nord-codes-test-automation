# nord-codes-test-automation

Автотесты для приложения `internal-0.0.1-SNAPSHOT.jar`. Внешний сервис, к которому обращается приложение, тесты подменяют сами — отдельно его запускать не нужно.

## Что нужно установить

- Java 17 или новее
- Maven 3.6.3 или новее
- Allure

## Как запустить тесты

1. Запустите приложение:
   ```
   java -jar -Dsecret=qazWSXedc -Dmock=http://localhost:8888/ internal-0.0.1-SNAPSHOT.jar
   ```
   Порт 8888 должен быть свободен: на нём тесты поднимут заглушку внешнего сервиса.

2. В отдельном терминале, из папки проекта, запустите тесты:
   ```
   mvn clean test
   ```
   По умолчанию тесты идут параллельно в 4 потока. Другие варианты:
   - только smoke: `mvn clean test -Dgroups=smoke`
   - только регресс: `mvn clean test -Dgroups=regression`
   - последовательно: `mvn clean test -Djunit.jupiter.execution.parallel.enabled=false`

3. Откройте отчёт:
   ```
   mvn allure:serve
   ```
   Отчёт откроется в браузере. Тесты сгруппированы по функциям во вкладке Behaviors, у каждого есть описание на русском и пошаговый ход проверки.

## Результат прогона

Всего 13 тестов: 12 проходят, 1 отключён из-за найденного дефекта (в отчёте он отмечен как Skipped).

## Найденный дефект

**Приложение не пускает пользователя с токеном, в котором есть буквы G-Z.**

По требованиям токен — это 32 символа из заглавных латинских букв и цифр (`A-Z0-9`), но приложение принимает только цифры и буквы от A до F.

Как воспроизвести:
```
curl -X POST http://localhost:8080/endpoint \
  -H "X-Api-Key: qazWSXedc" \
  -d "token=GHIJKLMNOPQRSTUVWXYZGHIJKLMNOPQR&action=LOGIN"
```

- Ожидаемый результат: `{"result":"OK"}`
- Фактический результат: код 400, `{"result":"ERROR","message":"token: должно соответствовать \"^[0-9A-F]{32}$\""}`

Этот сценарий проверяет тест `RequestValidationTest.loginWithLettersGToZTokenTest`. Он падает, поэтому временно отключён через `@Disabled`. После исправления дефекта аннотацию нужно убрать.
